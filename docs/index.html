Overview

AI-Ready 3層構造

「憲法 → 仕様 → 検証」の3層で、判断基準を人間にもAIにも読める形にしています。上位ほど人間向けの意図、下位ほど機械可読・自動検証に寄ります。

1
憲法 — DESIGN.md
非交渉の10原則。AIが最初に必ず読む、意図とトーンのソース。
↓
2
仕様 — contracts / tokens
機械可読のコンポーネント契約とデザイントークン（色・余白・角丸・影のSSOT）。
↓
3
検証 — lint / CI / check_rules
禁止パターンを自動検知。違反はCIとlintで通さない、品質のゲート。

Guidelines

Do / Don't

rules.json の代表8ルールを、実際のビフォー / アフターで示します。左（Don't）は避けるべき実装、右（Do）が推奨です。

1. DECOR_NO_CARD_COLOR_BAR
カード上部のカラーバーは禁止（AIっぽい装飾）。枠線のみで構成する。
×Don't
プロジェクトA
上部にカラーバーのある装飾カード
上辺に太いカラーバーを付けている
✓Do
プロジェクトA
枠線のみで構成した静かなカード
neutral-200 の枠線のみ
2. COLOR_NO_RAW_PALETTE
生のパレット色は禁止。primary / semantic のトークンを使う。
×Don't
意味を持たない生パレット色を直接指定
✓Do
セマンティックな primary トークン
3. ELEVATION_NO_HEAVY_SHADOW
shadow-lg 以上はオーバーレイ限定。通常UIは shadow-sm / md まで。
×Don't
重い影のカード
通常UIに強い影
通常カードに大きな影
✓Do
控えめな影のカード
shadow-sm で十分
shadow-sm の軽い立体感
4. FORM_NO_PLACEHOLDER_ONLY_LABEL
placeholder をラベル代わりにしない。label を必ず使う。
×Don't
placeholder だけ。入力すると項目名が消える
✓Do
label が常に見える
5. TEXT_NO_PURE_BLACK
純黒は使わない。text-neutral-900 を使う。
×Don't
純黒 #000000 の見出し
コントラストが硬く目が疲れる
✓Do
neutral-900 の見出し
やわらかい濃紺グレー
6. DECOR_NO_GRADIENT_BG
グラデーション背景は原則禁止。単色の neutral / primary を使う。
×Don't
派手なグラデーション
意味のない装飾背景
乱用されたグラデーション背景
✓Do
単色の落ち着いた背景
primary-50 のトーン
単色トークンで統一
7. UI_NO_EMOJI_LABEL
ボタン・見出し等のUIラベルに絵文字を使わない。
×Don't
絵文字と過剰な感嘆符
✓Do
簡潔・敬体のラベル
8. COMP_NO_REINVENT
@sevendot/ui に存在する部品を素のHTMLで再発明しない。
×Don't
自作の <div> ボタン
半端な余白・角丸・影で似せた独自実装
✓Do
